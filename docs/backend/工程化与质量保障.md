### 2.2 模块组织原则

#### ✅ 当前实践

**模块化设计**
- 每个业务域独立模块 (15个模块)
- 清晰的职责边界 (controller/service/module)
- 依赖注入驱动 (NestJS IoC 容器)

**分层架构**
```
Controller 层 (路由与参数校验)
    ↓
Service 层 (业务逻辑)
    ↓
Prisma 层 (数据访问)
    ↓
PostgreSQL (数据存储)
```

**共享模块**
- `common/`: 全局守卫、拦截器、管道
- `utils/`: 纯函数工具
- `config/`: 配置管理 (ConfigModule)
- `prisma/`: 数据库客户端单例

import { mockDeep, mockReset, DeepMockProxy } from 'jest-mock-extended';

  mockReset(prismaMock);

**3. 测试示例**
```typescript
// src-backend/users/users.service.spec.ts
describe('UsersService', () => {
  let service: UsersService;
  let prisma: DeepMockProxy<PrismaClient>;

  beforeEach(() => {
    prisma = prismaMock;
    service = new UsersService(prisma);
  });

  it('should find user by id', async () => {
    const mockUser = createMockUser({ id: 'test-123' });
    prisma.user.findUnique.mockResolvedValue(mockUser);

    const result = await service.findById('test-123');
    expect(result).toEqual(mockUser);
  });
});
```

### 4.4 契约测试 (API Contract Testing)

// test/contracts/auth.pact.spec.ts
import { Pact } from '@pact-foundation/pact';

describe('Auth API Contract', () => {
  const provider = new Pact({
    consumer: 'iPet-Frontend',
    provider: 'iPet-Backend',
  });

  it('POST /api/auth/login 返回 accessToken', async () => {
    await provider.addInteraction({
      state: 'user exists',
      uponReceiving: 'a login request',
      withRequest: {
        method: 'POST',
        path: '/api/auth/login',
        body: {
          email: 'test@example.com',
          password: 'Password123!',
        },
      },
      willRespondWith: {
        status: 200,
        body: {
          accessToken: Matchers.string(),
          user: {
            id: Matchers.uuid(),
            email: 'test@example.com',
          },
        },
      },
    });

    // 验证契约
    const response = await axios.post('/api/auth/login', {...});
    expect(response.data).toHaveProperty('accessToken');
  });
});

      - name: Upload coverage

  migration:

  build:
    runs-on: ubuntu-latest
    needs: migration
    if: github.ref == 'refs/heads/main'

      - uses: actions/checkout@v3
      - uses: docker/setup-buildx-action@v2
      - uses: docker/login-action@v2

          username: ${{ secrets.DOCKER_USERNAME }}

      - uses: docker/build-push-action@v4
        with:
          context: .
          push: true
          tags: |
            ${{ secrets.DOCKER_REGISTRY }}/ipet-backend:${{ github.sha }}
            ${{ secrets.DOCKER_REGISTRY }}/ipet-backend:latest

  # 5️⃣ 部署到生产环境
  deploy:
    runs-on: ubuntu-latest
    needs: build
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Deploy to Server
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            docker pull ${{ secrets.DOCKER_REGISTRY }}/ipet-backend:latest
            docker stop ipet-backend || true
            docker rm ipet-backend || true
            docker run -d \
              --name ipet-backend \
              -p 3000:3000 \
              --env-file /opt/ipet/.env \
              ${{ secrets.DOCKER_REGISTRY }}/ipet-backend:latest
```

### 5.3 数据库迁移策略

#### Prisma Migrate 工作流

**开发环境**:
```bash
# 1. 修改 schema.prisma
# 2. 创建迁移
npx prisma migrate dev --name add_user_avatar

# 3. 生成 Prisma Client
npx prisma generate
```

**生产环境**:
```bash
# CI/CD 自动执行
npx prisma migrate deploy  # 只应用迁移，不创建新迁移
```

#### 迁移安全规范

**危险操作检查清单**:
- [ ] 是否删除字段? → 先标记为 optional，观察一周后再删
- [ ] 是否重命名字段? → 使用数据迁移脚本
- [ ] 是否修改枚举值? → 确保向后兼容
- [ ] 是否添加 NOT NULL 约束? → 先添加默认值

**回滚策略**:
```bash
# 查看迁移历史
npx prisma migrate status

# 回滚到指定迁移 (需手动执行 SQL)
# Prisma 不支持自动回滚，需要:
# 1. 编写回滚 SQL
# 2. 在数据库执行
# 3. 同步 schema.prisma
```

  server backend-blue:3000;

# 3. 回滚时间: < 30 秒
```

### 5.5 健康检查与监控

#### 添加健康检查端点

```typescript
// src-backend/health/health.controller.ts
import { Controller, Get } from '@nestjs/common';
import { HealthCheck, HealthCheckService, PrismaHealthIndicator } from '@nestjs/terminus';

@Controller('health')
export class HealthController {
  constructor(
    private health: HealthCheckService,
    private db: PrismaHealthIndicator,
  ) {}

  @Get()
  @HealthCheck()
  check() {
    return this.health.check([
      () => this.db.pingCheck('database'),
    ]);
  }
}
```

### 6.3 现有架构决策补录

#### ADR-0001: 使用 NestJS 框架

**背景**: 需要选择后端框架

**候选方案**:
- Express.js (轻量级)
- Koa.js (现代化)
- NestJS (企业级)

**决策**: NestJS

**理由**:
- ✅ TypeScript 优先支持
- ✅ 依赖注入 + 模块化架构
- ✅ 内置守卫、拦截器、管道
- ✅ 与 Prisma 深度集成
- ✅ 活跃社区 + 完善文档

**权衡**:
- ❌ 学习曲线较陡 → 团队已掌握
- ❌ 包体积较大 → 性能影响可接受

---

#### ADR-0002: 使用 Prisma ORM

**背景**: 需要类型安全的 ORM

**候选方案**:
- TypeORM (NestJS 官方推荐)
- Sequelize (成熟稳定)
- Prisma (现代化)

**决策**: Prisma

**理由**:
- ✅ 自动生成类型定义
- ✅ 声明式 Schema
- ✅ 迁移管理完善
- ✅ 查询性能优秀

**权衡**:
- ❌ 不支持 MongoDB → 项目使用 PostgreSQL，无影响

---

#### ADR-0003: JWT 认证 + 游客模式

**背景**: 需要支持匿名用户与注册用户

**决策**: JWT + `isGuest` 标志位

**理由**:
- ✅ 无状态认证，易扩展
- ✅ 统一用户模型 (User 表)
- ✅ 无缝升级流程 (游客 → 正式用户)

**权衡**:
- ❌ 游客数据需定期清理 → 实现了定时任务

## 十、最佳实践与规范

### 10.1 NestJS 最佳实践

**1. 模块组织**
```typescript
// ✅ 推荐: 每个功能独立模块
@Module({
  imports: [PrismaModule],  // 依赖模块
  controllers: [PetsController],
  providers: [PetsService],
  exports: [PetsService],  // 供其他模块使用
})
export class PetsModule {}

// ❌ 避免: 所有逻辑都在 AppModule
```

**2. DTO 与 Entity 分离**
```typescript
// ✅ 推荐: 使用 DTO 校验输入
export class CreatePetDto {
  @IsString()
  @MinLength(1)
  name: string;

  @IsEnum(['dog', 'cat', 'bird'])
  type: string;
}

// ❌ 避免: 直接使用 Prisma 生成的类型作为输入
```

**3. 异常处理**
```typescript
// ✅ 推荐: 使用 NestJS 内置异常
throw new NotFoundException(`Pet with ID ${id} not found`);

// ❌ 避免: 抛出普通 Error
throw new Error('Not found');
```

### 10.2 Prisma 最佳实践

**1. 索引优化**
```prisma
// ✅ 推荐: 为常用查询添加索引
model HealthRecord {
  // ...
  @@index([petId, date(sort: Desc)])  // 时间范围查询
  @@index([petId, type])              // 类型过滤
}
```

**2. 关系定义**
```prisma
// ✅ 推荐: 明确级联删除策略
model Pet {
  id String @id @default(uuid())
  healthRecords HealthRecord[]
}

model HealthRecord {
  id String @id @default(uuid())
  petId String
  pet Pet @relation(fields: [petId], references: [id], onDelete: Cascade)
}
```

**3. 事务使用**
```typescript
// ✅ 推荐: 多表操作使用事务
await prisma.$transaction([
  prisma.user.delete({ where: { id } }),
  prisma.pet.deleteMany({ where: { userId: id } }),
]);

// ❌ 避免: 分别调用，可能部分失败
await prisma.user.delete({ where: { id } });
await prisma.pet.deleteMany({ where: { userId: id } });
```

### 10.3 TypeScript 最佳实践

**1. 避免 any**
```typescript
// ✅ 推荐: 定义明确类型
interface CreatePetPayload {
  name: string;
  type: 'dog' | 'cat' | 'bird';
}

// ❌ 避免
function createPet(data: any) { ... }
```

**2. 使用类型保护**
```typescript
// ✅ 推荐
if (user.isGuest) {
  // TypeScript 知道这里 user.email 可能为 null
  if (!user.email) return;
}

// ❌ 避免: 强制类型转换
const email = user.email!;  // 危险!
```
