# 安全与合规层

> **版本**: v1.0  
> **更新时间**: 2025-12-18  
> **维护团队**: 架构组、安全组

本文档定义 iPet 项目的数据安全、隐私合规和安全审计规范,确保应用符合隐私保护要求，降低安全风险。

## 1. 数据安全

### 1.1 加密策略

#### 1.1.1 传输加密
- **HTTPS Only**: 生产环境强制使用 HTTPS
  - API Base URL: `https://api.zhengjiyuan.top/api`
  - 所有敏感数据传输必须通过 TLS 1.2+ 加密
  - 本地开发环境可使用 HTTP，但需明确标识

#### 1.1.2 存储加密
- **Token 存储**: 
  - Access Token 和 Refresh Token 存储在 `uni.storage` (微信小程序为加密存储)
  - 文件位置: [`authStorage.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/utils/business/authStorage.ts)
  - 存储策略:
    ```typescript
    const TOKEN_STORAGE_KEY = 'token'
    const TOKEN_EXPIRES_AT_KEY = 'token_expires_at'
    uni.setStorageSync(TOKEN_STORAGE_KEY, token)  // 同步存储
    ```
  - **注意**: 微信小程序的 storage 本身已加密，无需额外加密

- **敏感字段规范**:
  - 用户密码: 仅在注册/登录时明文传输（HTTPS 保护），后端必须加密存储（bcrypt/argon2）
  - Email: 不脱敏，但需权限控制
  - 健康记录: 本地缓存不加密，依赖平台存储安全

#### 1.1.3 加密算法要求
- 传输层: TLS 1.2+（由 HTTPS 提供）
- 后端存储: 
  - 密码: bcrypt (cost >= 10) 或 argon2
  - Token: JWT with RS256/HS256
- 前端不进行密码学加密处理，依赖后端和传输层保护

### 1.2 数据脱敏

#### 1.2.1 日志脱敏
- **禁止记录的敏感字段**:
  - 密码 (password)
  - Token (accessToken, refreshToken)
  - 完整 Email（如需记录，使用 `m***@example.com` 格式）

- **实施规范**:
  ```typescript
  // ❌ 错误示例
  console.log('Login success:', { email, password, token })
  
  // ✅ 正确示例
  console.log('Login success:', { 
    email: maskEmail(email),  // m***@example.com
    userId: user.id 
  })
  ```

- **日志审查**: 
  - 所有涉及用户数据的日志必须经过脱敏审查
  - 线上环境禁止打印完整 Token 和密码

#### 1.2.2 前端展示脱敏
- **密码输入框**: 
  - 使用 `password` 类型，默认隐藏
  - 提供「显示/隐藏」切换按钮
  - 文件: [`login/index.vue`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/pages/login/index.vue)

- **敏感词过滤**:
  - 用户评论、备注等 UGC 内容需过滤敏感词
  - 配置文件: [`sensitiveWords.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/config/sensitiveWords.ts)
  - 使用 `@shared/validation/sensitiveWords` 模块

### 1.3 权限边界

#### 1.3.1 路由权限控制
- **权限级别**:
  ```typescript
  type RouteAuthLevel = 'public' | 'guest' | 'user'
  ```
  - `public`: 无需登录（登录页、注册页、帮助页面）
  - `guest`: 游客可访问（基础功能）
  - `user`: 需正式账号（高级功能，如数据导出）

- **实现机制**:
  - 文件: [`permission.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/permission.ts)
  - 使用 `uni.addInterceptor` 拦截路由跳转
  - Token 有效性检查（30秒缓冲期）:
    ```typescript
    const TOKEN_EXPIRY_BUFFER_MS = 30 * 1000
    if (expiresAt - TOKEN_EXPIRY_BUFFER_MS <= now) {
      return { valid: false, reason: 'expired' }
    }
    ```

- **公开路由配置**:
  ```typescript
  const publicExactRoutes = [
    '/pages/login/index',
    '/pages/register/index',
    '/pages/login/forgot-password',
    '/pages/settings/privacy'  // 隐私设置允许未登录访问
  ]
  
  const publicPrefixes = [
    '/pages/articles/',   // 文章页面公开
    '/pages/help/',       // 帮助页面公开
    '/pages/about/'       // 关于页面公开
  ]
  ```

#### 1.3.2 API 权限控制
- **认证方式**:
  - Bearer Token 认证
  - 请求头: `Authorization: Bearer <accessToken>`
  - 实现文件: [`request.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/utils/common/request.ts)

- **Token 刷新机制**:
  - 401 自动刷新: 使用 Refresh Token 获取新 Access Token
  - 刷新失败: 强制登出，清除所有本地数据
  - 队列重试: 401 期间的请求会排队，刷新成功后自动重试

  ```typescript
  // 401 处理逻辑
  if (statusCode === 401 && !config.__retry && !config.skipAuthRefresh) {
    queueFailedRequest(config, resolve, reject)
    triggerTokenRefresh()
    return
  }
  ```

- **跳过认证的接口**:
  - `/auth/login`
  - `/auth/register`
  - `/auth/guest`
  - `/auth/refresh` (使用 Refresh Token)

#### 1.3.3 数据隔离
- **多租户隔离**:
  - 每个用户只能访问自己的数据
  - 后端必须验证 `userId` 和 Token 的一致性
  - 前端通过 `userStore.currentUser.id` 获取当前用户

- **游客数据隔离**:
  - 游客数据标记 `isGuest: true`
  - 游客数据默认**不持久化到服务器**
  - 升级为正式账号后，数据转移（需后端支持）

### 1.4 敏感字段规范

#### 1.4.1 字段分类
| 字段类型 | 敏感级别 | 存储要求 | 传输要求 | 日志要求 |
|---------|---------|---------|---------|---------|
| 密码 | 🔴 高 | 后端加密存储 | HTTPS | **禁止记录** |
| Token (Access/Refresh) | 🔴 高 | uni.storage | HTTPS | **禁止记录** |
| Email | 🟡 中 | 明文 | HTTPS | 脱敏记录 |
| 用户 ID | 🟢 低 | 明文 | HTTPS | 可记录 |
| 健康记录 | 🟡 中 | 明文（缓存） | HTTPS | 可记录（不含敏感备注） |
| 宠物照片 URL | 🟢 低 | 明文 | HTTPS | 可记录 |

#### 1.4.2 代码审查检查点
- [ ] 所有 `password` 字段不得出现在日志中
- [ ] Token 不得在非必要情况下打印
- [ ] Email 在日志中必须脱敏
- [ ] 健康记录中的用户备注不得包含敏感词

## 2. 隐私合规

### 2.1 数据保存期限

#### 2.1.1 用户数据
- **正式账号**:
  - 保存期限: **永久**（直到用户主动删除账号）
  - 包括: 用户资料、宠物信息、健康记录、文章收藏

- **游客账号**:
  - 保存期限: **不持久化到服务器**
  - 本地缓存: 依赖设备存储，用户卸载应用后自动清除
  - **注意**: 游客数据升级为正式账号后，数据转为永久保存

#### 2.1.2 缓存数据
- **本地缓存**:
  - 健康记录缓存: 
    - 默认保留最近 **90 天**数据
    - 超过 90 天的数据自动过期（由 `CacheManager` 管理）
    - 文件: [`CacheManager.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/utils/cache/CacheManager.ts)

  - 图片缓存:
    - 默认保留 **30 天**
    - LRU 策略: 缓存满时淘汰最久未使用的图片
    - 文件: [`imageCacheStore.ts`](file:///Users/zhengjiyuan/Desktop/iPet/iPet-uniapp/src/stores/imageCacheStore.ts)

- **会话数据**:
  - Token 有效期: **30 天**（由后端设置 `expiresIn`）
  - 超过有效期自动刷新或强制登出

```yaml
    runs-on: ubuntu-latest

      - uses: actions/checkout@v3
      
      # 1. 依赖漏洞扫描
      - name: Install dependencies
        run: npm ci
      
      - name: Run npm audit
        run: npm audit --production --audit-level=moderate
      
      # 2. 静态代码扫描
      - name: Run ESLint security rules
        run: npx eslint . --ext .ts,.vue --config .eslintrc.security.js
      
      # 3. 敏感信息扫描
      - name: Scan for secrets
        uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: ${{ github.event.repository.default_branch }}
      
      # 4. 类型检查
      - name: Type check
        run: npm run type-check
```

## 4. 安全事件响应

### 4.1 安全事件分级
| 级别 | 定义 | 示例 | 响应时间 |
|-----|------|------|---------|
| P0 | 数据泄露、服务中断 | Token 泄露、数据库被删 | **立即** (1 小时内) |
| P1 | 高危漏洞被利用 | SQL 注入被发现 | **紧急** (4 小时内) |
| P2 | 中危漏洞或滥用 | 恶意刷接口 | **优先** (24 小时内) |
| P3 | 低危或可疑行为 | 异常登录尝试 | **常规** (1 周内) |

### 4.2 应急处理流程
1. **发现阶段**: 
   - 监控告警（如异常 API 请求量）
   - 用户反馈
   - 漏洞扫描发现

2. **评估阶段**:
   - 确定影响范围（影响用户数、数据类型）
   - 判定级别 (P0-P3)

3. **控制阶段**:
   - **P0/P1**: 立即下线受影响功能或接口
   - 封禁异常 Token/IP
   - 通知安全组和技术负责人

4. **修复阶段**:
   - 修复漏洞并测试
   - 发布紧急补丁
   - 通知受影响用户（如涉及数据泄露）

5. **复盘阶段**:
   - 编写事件报告
   - 优化监控和预防措施
   - 更新安全规范
