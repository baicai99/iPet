# 文章管理规则（评审版 PRD 落档）

## 规范背景
文章管理需要统一标签、置顶语义、分类归属与阅读量统计规则，避免前端硬编码与数据不可追溯。

## 适用对象
- Backend
- Backend-UI
- UniApp

## 约束规则
- **标签强制**：所有文章必须绑定至少一个标签，不允许空标签文章。
- **置顶分层**：
  - Section 置顶：影响 Summary View 与文章总列表排序。
  - 类目置顶（指标置顶）：仅影响指标 Detail 页的文章区域排序。
- **分类由后端维护**：前端仅渲染后端返回的分类列表，不自行约定分类。
- **阅读量统计**：阅读量必须由后端 API 访问行为累积，前端不得模拟或本地累加。

## Step 0：边界与规则（一次评审定稿）

### 1. 分类删除策略（二选一）
- **选择：允许删除，但必须迁移**。删除分类前需选择迁移目标分类；后端先批量迁移该分类下文章到目标分类，再删除分类实体。若分类下无文章，可直接删除。

### 2. 批量操作范围
- 当前**不支持批量操作**，仅提供单条发布/编辑/删除。若后续需要批量删除/批量改分类/批量置顶，必须新增后端 API 与权限并更新本规范。

### 3. 权限粒度（最小集）
- 最小集：管理员登录可访问文章管理；删除操作需 `article:delete` 权限；列表/查看/新建/编辑沿用管理员登录校验（暂不拆分到独立权限）。

## 类型定义（类型先行）
```ts
export type ArticlePinScope = 'section' | 'metric'
```

## 分类管理（可治理实体）

### 规范背景
分类不再是前端固定选项，需要支持后台可治理的新增/编辑/排序/删除。

### 适用对象
- Backend
- Backend-UI
- UniApp

### 约束规则
- 分类为后端可治理实体，前端仅展示与选择，不缓存硬编码分类。
- `key` 作为稳定标识，创建后不可修改；可编辑 `label` 与 `order`。
- 删除分类必须指定迁移目标分类（若分类下有文章）；迁移后才允许删除，避免出现“无分类且不可编辑”的文章。
- 新增/编辑/删除分类后，文章列表与表单需支持刷新分类选项以同步最新数据。

### 示例
```json
{
  "key": "health",
  "label": "健康医疗",
  "order": 5
}
```

## 关键字段约定
- `tags: string[]`：文章标签，至少 1 项。
- `sectionPinned: boolean`：是否 Section 置顶。
- `sectionPinnedAt?: string`：Section 置顶生效时间，用于排序。
- `pinnedMetrics: string[]`：类目置顶（指标 key 列表）。
- `views: number`：阅读量，由后端统计。

## 示例
### 文章分类返回
```json
[
  { "key": "education", "label": "科普", "order": 1 },
  { "key": "recipe", "label": "狗饭", "order": 2 }
]
```

### 文章数据示例
```json
{
  "id": "weight",
  "title": "体重指标解释",
  "summary": "体重指标的意义与解读方式",
  "category": "education",
  "tags": ["weight", "body"],
  "sectionPinned": true,
  "sectionPinnedAt": "2025-12-31T10:00:00Z",
  "pinnedMetrics": ["weight"],
  "views": 128,
  "content": "# 体重指标解释\n..."
}
```
