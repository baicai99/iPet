下面给你一份「UniApp（H5/Web）迁移到小程序」的**样式迁移整改文档**模板，核心是：按维度拆解问题 → 按步骤推进 → 每一步都有可量化验收指标，避免“改到差不多”。

---

## 1. 迁移目标与基本原则

**目标**：同一套页面在小程序端达到“结构不乱、文字不炸、交互可用、适配稳定”。

**原则**

1. 先“定规范”，再“逐页修”。不要一边改一边换单位/布局方案。
2. 先解决“全局问题”（单位、字体、滚动、定位），再处理组件细节。
3. 改动尽量“可回归”：每一类问题给出固定的写法（组件库/工具函数/混入）。

---

## 2. 样式迁移的核心维度清单（每个维度都给指标）

### 维度A：单位与视口体系（px/rem/vw/vh → rpx/布局约束）

**常见问题**：H5 用 `vw/vh/rem`、`100vh`、`calc()`，到小程序出现高度不对、底部被 tabbar/安全区遮挡、字体缩放异常。
**改造动作**

* 统一设计基准：**全部布局用 rpx（或 upx）**；尽量减少 `vw/vh`。
* **100vh 实战验证** ✅：
  * **结论**：小程序环境下 `100vh` **可以安全使用**
  * **场景**：全屏布局（登录页、引导页等）需要垂直居中时
  * **原因**：小程序的 `100vh` = 可视区域高度（不包含 tabbar），不会被遮挡
  * **最佳实践**：
    ```scss
    .page-container {
        height: 100vh; // ✅ H5 和小程序通用
        display: flex;
        align-items: center; // 需要固定高度才能垂直居中
        justify-content: center;
    }
    ```
  * **避免**：`min-height: auto` 会让容器失去高度，导致 flex 居中失效
* `calc()`、`env(safe-area-*)` 等高级写法：用 **编译期 SCSS 变量/运行时 padding** 替代（安全区用 `safeArea` 计算）。
  **验收指标**
* iOS/Android 主流机型：首屏容器不被遮挡；底部按钮区可点到（无遮挡）。
* 页面不出现“上下抖动/忽大忽小”的高度变化。
* 同一页面在不同宽度下：关键模块宽度不溢出、不挤压（无横向滚动条）。
* Flex 垂直居中布局在小程序中表现正常。

---

### 维度B：布局模型（Flex/Grid/浮动/定位）

**常见问题**：flex 在小程序端表现差异、`position: fixed` 跟随滚动异常、父子高度计算不同。
**改造动作**

* 列表/表单：优先 **flex**，少用复杂嵌套 + `height: 100%` 链式依赖。
* 尽量不用 CSS Grid（视基础库支持而定），可改为 flex + 换行。
* “吸底按钮/悬浮按钮”：优先用页面结构实现（底部占位 + 内容滚动），少用纯 fixed 硬顶。
  **验收指标**
* 列表/卡片：对齐误差肉眼不可见（不出现某一列跳动）。
* 吸底操作区：滚动到任意位置都可见且不遮挡内容（底部留白正确）。
* 长内容页面：不会出现 fixed 层遮住输入框/按钮。

---

### 维度C：滚动体系（body滚动 → scroll-view / 页面滚动差异）

**常见问题**：H5 依赖 `overflow: auto`、自定义滚动容器，到小程序不滚/滚动穿透/滚动卡顿。
**改造动作**

* 能用页面原生滚动就别造滚动容器。
* 必须局部滚动：用 `scroll-view`，并控制高度来源（别依赖 `100%` 链）。
* 弹窗/抽屉：处理滚动穿透（遮罩层 + 禁止背景滚动的统一方案）。
  **验收指标**
* 局部滚动容器：滚动顺滑，不出现“滚两下卡住”。
* 弹窗打开时：背景不滚动；关闭后恢复正常。
* 长列表：滚动时不出现明显掉帧（肉眼可感知的卡顿要消除）。

---

### 维度D：文字与字体（字号、行高、截断、自动换行）

**常见问题**：字体渲染差异导致换行点变化、文字溢出、line-height 不一致。
**改造动作**

* 统一全局字体与字号梯度（在 `uni.scss` 里做 token，如 `--font-sm/md/lg` 或 SCSS 变量）。
* 文本组件：明确 `line-height`，列表标题统一用 `1.2~1.5` 的固定策略。
* 多行省略：小程序环境对多行截断支持差异，优先使用框架/组件提供方案或降级为单行。
  **验收指标**
* 关键文本（标题/金额/按钮文案）不换行、不截断或截断符合设计预期。
* 表单/列表：同一行高度一致，不出现“某个手机行高变胖”。

---

### 维度E：图标与资源（Iconfont、背景图、网络资源限制）

**常见问题**：`@font-face` 引用网络字体失败、svg/背景图路径不对、资源体积超限。
**改造动作**

* Iconfont：优先用 **图片精灵/内置字体文件打包/组件化图标**，避免远程字体依赖。
* 背景图：统一走 `static/`（或平台要求目录），用相对路径；避免跨域。
* 图片适配：统一 `mode`（如宽高自适应策略），避免拉伸变形。
  **验收指标**
* 所有图标 100% 显示（无空白方块/丢失）。
* 首屏关键图片不变形；不同机型裁切一致。
* 包体/分包后资源加载无 404。

---

### 维度F：交互态与可点击区域（hover/active、点击穿透、手势）

**常见问题**：H5 的 `:hover`、点击态、手势库在小程序不一致；按钮可点区域太小。
**改造动作**

* 交互态：统一用 `:active` 或组件内状态类名控制；不要依赖 H5 hover。
* 可点区域：按钮/列表项点击热区做 padding 扩大。
* 弹层：重点排查点击穿透与层级（z-index）。
  **验收指标**
* 所有可点击元素：手指好点，不需要“精准点字”。
* 弹层打开时：点击遮罩能关闭；遮罩下内容点不到。

---

### 维度G：样式作用域与组件隔离（scoped、深度选择器、第三方组件）

**常见问题**：H5 里用深选择器改第三方组件样式，小程序端失效；全局样式污染。
**改造动作**

* 三方组件样式改造：优先使用组件提供的 `class`/`custom-style`/`externalClasses` 类似入口。
* 深度选择器只作为兜底，并且按平台做条件编译。
* 抽出“页面壳”与“业务组件”的样式边界：业务组件尽量不依赖页面上下文。
  **验收指标**
* 页面之间样式互不影响（A页不把B页按钮样式改了）。
* 三方组件在小程序端样式可控且稳定。

---

### 维度H：兼容性黑名单（小程序不支持/支持不完整的 CSS 特性）

**常见风险点**（建议直接列为项目黑名单）

#### CSS 选择器黑名单 ❌

| 选择器 | 问题 | 替代方案 | 示例 |
|--------|------|---------|------|
| `> *` | 通用子选择器不支持 | 明确列出标签 | `view, text, button, image` |
| `> *:last-child` | 同上 | 列出具体标签 | `view:last-child, text:last-child` |
| `:nth-child(n+3)` | 部分复杂伪类支持差 | 用类名标记 | `.item-3, .item-4` |

**实战案例**：`AppSectionState.vue` 修复
```scss
// ❌ 小程序不支持
.container {
    > * {
        margin-bottom: 16rpx;
    }
    > *:last-child {
        margin-bottom: 0;
    }
}

// ✅ 改为支持的标签选择器
.container {
    view, text, button, image {
        margin-bottom: 16rpx;
    }
    view:last-child, text:last-child, button:last-child, image:last-child {
        margin-bottom: 0;
    }
}
```

#### 其他 CSS 特性黑名单

* ❌ `filter/backdrop-filter`：部分效果不支持或性能差
* ⚠️ `position: sticky`：行为差异，需充分测试
* ⚠️ `overflow` 与圆角裁切：配合使用可能出现渲染异常
* ❌ 远程 `@font-face`：小程序不支持网络字体

**改造动作**
* 建立"样式黑名单 + 替代写法"文档：发现一次记录一次，后续照抄替代方案。
* 在 ESLint/StyleLint 中配置规则，禁止使用黑名单特性。

**验收指标**
* 黑名单项在代码里"可搜索为 0"（例如搜索 `> \*`、远程字体等）。
* WXSS 编译无错误、无警告。

## 3. 推荐迁移流程（步骤性 + 指标性）

### Step 0：建立对照与基线

* 动作：H5 关键页面截图基线（首屏/中部/底部、弹窗态）。
* 指标：每个页面至少 3 张基线图；后续对照差异一眼能看出。

### Step 1：先改“全局样式层”

* 动作清单：

  1. 统一单位策略（rpx/upx）
  2. 统一字体、行高、颜色 token（`uni.scss`）
  3. 统一安全区策略（底部 padding / 吸底容器）
  4. 统一弹层/遮罩/滚动穿透方案
* 验收指标：改完后选 2~3 个页面抽检，**不出现遮挡、溢出、滚动异常**。

### Step 2：搭“布局骨架”，再补细节

* 动作：每个页面先只保证结构（容器、模块、间距），后处理圆角/阴影/动画。
* 指标：页面结构完成时，内容不乱、无横向滚动条、吸底区正确。

### Step 3：逐组件整改（高复用优先）

优先顺序建议：

1. 导航栏/自定义头部（含状态栏高度）
2. 列表项卡片（最容易出现对齐/溢出）
3. 弹窗/抽屉/下拉选择（滚动穿透+层级）
4. 表单输入（键盘顶起、fixed 冲突）

* 指标：每改完一个组件，至少在 2 个页面复用验证通过。

### Step 4：逐页回归（按场景验收）

每页最少验收场景：

* 首屏、长内容滚动、弹层打开、表单输入（如有）、弱网/慢机加载（如有图多）。
* 指标：关键路径无阻断（能看、能点、能提交/能关闭）。

### Step 5：建立“问题库 → 规则化修复”

* 动作：把所有踩坑沉淀为：**触发条件 → 现象 → 原因 → 标准修复写法 → 可搜索关键字**
* 指标：后续新页面迁移，80% 问题可以直接套用既有写法解决。

## 5. 设计系统应用最佳实践 ⭐

### 5.1 颜色标准化

**目标**：消除硬编码颜色，使用设计系统变量，便于主题切换和全局调整。

**项目颜色变量体系**（位于 `src/styles/theme-variables.scss`）：

| 变量名 | 语义 | 示例值 | 使用场景 |
|--------|------|--------|---------|
| `--app-background` | 主背景色 | `#f2f1f5` | 页面背景 |
| `--app-card-bg` | 卡片背景 | `#ffffff` | 卡片、输入框、按钮背景 |
| `--app-navbar-bg` | 导航栏背景 | `#fbfbfd` | 顶部导航栏、底部 tabbar |
| `--app-border-color` | 边框颜色 | `#f3f4f6` | 分割线、输入框边框 |
| `--app-text-primary` | 主要文本 | `#1f2937` | 标题、正文 |
| `--app-text-secondary` | 次要文本 | `#4b5563` | 描述、辅助信息 |
| `--app-text-muted` | 弱化文本 | `#9ca3af` | 提示、标签 |
| `--app-active-bg` | 激活态背景 | `#f9fafb` | hover/active 状态 |

**实战案例**：登录页面重构

```scss
// ❌ 重构前：硬编码颜色
.input-container {
    background-color: #ffffff;
    border: 1px solid #f1f5f9;
    color: #1e293b;
}

.footer-text {
    color: #94a3b8;
}

// ✅ 重构后：使用设计系统变量
.input-container {
    background-color: var(--app-card-bg);
    border: 1px solid var(--app-border-color);
    color: var(--app-text-primary);
}

.footer-text {
    color: var(--app-text-muted);
}
```

**收益**：
- ✅ 颜色语义化，代码可读性提升
- ✅ 全局颜色统一调整（只需修改变量定义）
- ✅ 未来支持暗色模式（重新定义变量值即可）

---

### 5.2 字体标准化（Typography Mixins）

**目标**：消除硬编码字号，使用 Typography Mixins，确保文本层级清晰、全局一致。

**项目 Typography 体系**（位于 `src/uni.scss`）：

| Mixin | 字号 | 字重 | 行高 | 使用场景 |
|-------|------|------|------|---------|
| `@include text-large-title;` | 56rpx | 700 | 1.2 | 页面大标题（登录页标题）|
| `@include text-title-2;` | 36rpx | 600 | 1.3 | 二级标题（卡片标题）|
| `@include text-headline;` | 28rpx | 600 | 1.4 | 小标题（section 标题）|
| `@include text-body;` | 28rpx | 400 | 1.5 | 正文、按钮文字、输入框 |
| `@include text-subhead;` | 24rpx | 400 | 1.4 | 副标题、小提示 |
| `@include text-caption-1;` | 20rpx | 400 | 1.3 | 说明文字 |
| `@include text-caption-2;` | 18rpx | 500 | 1.3 | 标签、极小文字 |

**实战案例**：登录页面文本层级

```scss
// ❌ 重构前：硬编码字号
.title {
    font-size: 48rpx;
    font-weight: 900;
    line-height: 1.2;
}

.input-label {
    font-size: 18rpx;
    font-weight: bold;
}

.footer-text {
    font-size: 22rpx;
    font-weight: 500;
}

// ✅ 重构后：使用 Typography Mixins
.title {
    @include text-large-title;
    // 自动包含字号、字重、行高
}

.input-label {
    @include text-caption-2;
}

.footer-text {
    @include text-subhead;
}
```

**收益**：
- ✅ 字体大小统一规范，符合视觉层级
- ✅ 减少代码量（自动包含字号、字重、行高）
- ✅ 全局字体调整（一处修改，全局生效）

### 5.3 设计系统迁移清单

**步骤 1**：建立颜色映射表

将现有硬编码颜色映射到设计系统变量：

| 硬编码颜色 | → | 设计系统变量 |
|-----------|---|-------------|
| `#ffffff` | → | `var(--app-card-bg)` |
| `#f8fafc`, `#f2f1f5` | → | `var(--app-background)` |
| `#1e293b`, `#1f2937` | → | `var(--app-text-primary)` |
| `#94a3b8`, `#64748b` | → | `var(--app-text-muted)` |
| `#f1f5f9`, `#e2e8f0` | → | `var(--app-border-color)` |

**步骤 2**：建立字号映射表

| 硬编码字号 | → | Typography Mixin |
|-----------|---|-----------------|
| `48rpx` - `56rpx` | → | `@include text-large-title;` |
| `32rpx` - `36rpx` | → | `@include text-title-2;` 或 `@include text-headline;` |
| `28rpx` | → | `@include text-body;` |
| `24rpx` | → | `@include text-subhead;` |
| `18rpx` - `20rpx` | → | `@include text-caption-2;` 或 `@include text-caption-1;` |

**步骤 3**：逐组件替换

1. 搜索硬编码颜色（如 `#ffffff`、`#1e293b`）
2. 根据语义替换为对应变量
3. 搜索硬编码字号（如 `font-size: 28rpx`）
4. 替换为对应 mixin
5. 测试验证（视觉一致性、小程序编译通过）

**验收指标**：
- ✅ 组件中无硬编码颜色（品牌色除外）
- ✅ 组件中无硬编码字号
- ✅ 代码行数减少（mixin 自动包含多个属性）
- ✅ 视觉效果保持一致或更优
